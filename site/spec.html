제품 전체 스펙

결정론 엔진 + LLM 분석의 하이브리드 아키텍처. 파이프라인 각 단계는 JSON 계약으로 연결되고, 영속 저장되어 사람이 끼어들어 수정·재실행할 수 있다 — 이것이 "제어 가능".

1. 시스템 구조 (파이프라인)

단계역할방식
S1 IngestMarkdown 기획 → 정규화 IR(JSON)LLM
S2 ConceptIR → 컨셉 3종 + 토큰 시드LLM (Phase 3)
S3 DesignSys시드 → 전체 토큰 확장엔진(결정론)
S4 PagesIR × Pattern → 컴포넌트 트리엔진 + LLM 폴백
S5 Prototype페이지 링크 · User Flow 연결엔진
S6 Render트리 → HTML/CSS엔진(Handlebars)

2. 데이터 모델

  • Project — planningInputId, conceptIds[], selectedConceptId, designSystemId, pageIds[], prototypeId
  • PlanningInputIR — prd, ia[], userFlows[], uxPolicy[], uxWriting, pages[]( id, name, archetype, dataShape, fields[])
  • Concept — name, mood[], rationale, tokenSeed
  • DesignSystem — conceptId, tokens, components[] (외부 주입 가능 — 온사이트DS든 생성DS든 동일 입력)
  • Page — specId, layoutRecipeId, tree(ComponentNode)
  • Prototype — links[ fromPage/Node → toPage, transition ]

archetype ∈ Dashboard·List·Detail·Form·Setting·Login·Monitoring — 패턴화 가능 영역을 enum으로 고정. 제어의 뼈대.

3. Design Token — 3-tier (DTCG)

Tier 1 Primitiveblue-500, gray-100, space-1..12 — 컴포넌트 직접참조 금지
Tier 2 Semanticcolor.bg/fg/primary/border — 다크모드·테마는 이 레이어만 교체
Tier 3 Componentbutton.bg = {color.primary} — 컴포넌트가 참조하는 유일 레이어

스페이싱 4·8·12·16·24·32·48·64 (8pt). 타입 12/14/16/20/24/32/40, line-height 본문 1.5(한글 1.45~1.6)·헤딩 1.25. DTCG 포맷 → Figma Variables 연동 거의 공짜.

4. Component Library

컴포넌트 = 스키마(계약) + 렌더 템플릿 2파일. LLM은 스키마만 보고 조립, 픽셀은 모름. 스키마에 a11y 필드(role/focusRing/minTarget) 내장 → 접근성 기본 보장. MVP 세트: Button·Input·Select·Card·Table·Tag·Nav·Modal·Tabs·Stat·EmptyState·Avatar.

5. Pattern Library

archetype별 "페이지 레시피" — 어느 region(slot)에 어떤 컴포넌트가 들어가는지 규칙 + uxPolicyHooks(emptyState/loading 등). 핵심 가설의 구현체. 새 제품 = 패턴 재사용 + 토큰만 교체.

6. Layout Recipe

페이지 골격(shell) — 패턴과 분리, 여러 패턴이 공유. grid areas + 반응형 규칙 선언 → 생성물 자동 반응형. MVP: shell-sidebar · shell-topbar · centered.

7. 생성 방식

컨셉 → 디자인 시스템

LLM은 토큰값을 직접 안 만든다. 좁은 ConceptSeed(primaryHue, density, radius, fontPair, contrastTarget)만 생성 → 엔진이 컬러 ramp·WCAG 대비·스케일을 알고리즘으로 확장. 환각이 토큰값에 침투 못 함.

디자인 시스템 → 페이지

pattern + layout으로 트리 결정론 조립 → UX라이팅 주입 → UX정책 규칙 강제(삭제→확인모달 등) → 토큰 바인딩. LLM은 슬롯↔필드 매핑이 애매할 때만 폴백.

8. HTML 출력 / Figma 확장

토큰 = CSS Custom Properties, 다크모드 = [data-theme] 토글. 트리 → Handlebars 재귀 렌더. Render 단계에 어댑터(HtmlRenderer | FigmaRenderer) 추가로 확장 — 같은 트리/토큰 모델 공유라 비용 낮음. DTCG → Figma Variables, 스키마 variants → Component/Variant, layout areas → Auto Layout.
