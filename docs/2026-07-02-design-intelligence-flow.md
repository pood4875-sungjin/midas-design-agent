# AI 디자인시스템·UI 생산 툴 — 개정 Flow (근거장치 반영)

- **작성일**: 2026-07-02
- **기반**: 사용자 12단계 flow + 온사이트 rulebook 실전 검증 교훈
- **핵심 변경**: 정량 기준에 **근거+신뢰도** 강제 · 계층 **소유권 분리** · **자산/제품루프 2상 분리** · **소스 게이트** · 검수 **이진화** · **exemplar** 도입
- **연계**: [rulebook](../rulebook/README.md), [설계 스펙](2026-07-02-generation-policy-agent-design.md)

원본 flow는 큰 그림이 탄탄하다. 이 문서는 원본이 빠뜨린 **"정량값 자체의 근거장치"**를 채운 개정판이다. 원본의 12단계는 그대로 살리되, 성패를 가르는 4개 구멍을 메운다.

---

## 0. 왜 개정하나 (원본의 4구멍)

| 구멍 | 증상 | 처방 |
|------|------|------|
| 정량 기준 근거 없음 | "radius 10-14"의 출처 불명 = 또 다른 추측 | **근거+신뢰도 스키마** 강제 |
| 계층 4개 경계 겹침 | Seed·Visual 둘 다 radius/컬러 언급 → 충돌 | **소유권 표** |
| 검수 "80점" LLM 자기채점 | 재현 안 됨, 캘리브레이션 없음 | **이진 체크리스트 + 앵커** |
| PRD→바로 시안 | 소스 없이 추측 → 비주얼 빗나감(온사이트 실증) | **소스 게이트** |

## 1. 2상 분리 — 자산 vs 제품 루프 (원본에 없던 핵심 구분)

원본 12단계는 매 제품마다 다 도는 것처럼 읽힌다. 실제로는 두 층이다.

### 층 A — 디자인 지능 자산 (느리게 성장, 재사용)
1회성 셋업 후 계속 축적. 제품마다 새로 안 만든다.
- Global Standard (품질 헌법)
- Seed 라이브러리
- Visual Direction 라이브러리
- Product Pattern 카탈로그
- **Exemplar 라이브러리** (신규 — 아래 §5)

### 층 B — 제품 생산 루프 (제품마다 반복)
브리프 → 3시안 → 검수 → 선택 → Full DS → 토큰/코드 → 다화면 확장

> 층 A가 얇으면 층 B가 추측투성이가 된다. 층 A를 실측·exemplar로 두껍게 하는 게 이 툴의 진짜 자산.

## 2. 계층 소유권 표 (겹침 제거)

무엇을 **누가 최종 결정**하는지 못박는다. 겹치면 아래 규칙.

| 속성 | Global Standard | Seed (구조값) | Visual Direction (적용 강도) | Product Pattern |
|------|:---:|:---:|:---:|:---:|
| 품질 하한(안티패턴) | ● | | | |
| 컬러 **스케일/토큰값** | | ● | | |
| 컬러 **사용 비율/면적** | | | ● | |
| 타이포 **스케일** | | ● | | |
| 타이포 **위계 강도** | | | ● | |
| spacing/radius **스케일값** | | ● | | |
| 밀도·여백 **강도** | | | ● | |
| 그림자 **깊이 정도** | | | ● | |
| 화면 **정보구조·CTA배치** | | | | ● |
| 상태값(빈/로딩/에러) | ● 규칙 | | | ● 배치 |

**겹침 규칙**: **Seed가 "값", Visual이 "비율/강도".** 예 — radius 스케일 후보(8/10/12/14) = Seed. 이 제품에서 "라운드 감도 낮게 → 10 고정" = Visual. 충돌 시 Seed 범위 안에서 Visual이 선택.

## 3. 근거 스키마 — 모든 정량 기준에 강제 (최우선)

원본의 "radius 10-14px"는 그대로 두면 추측이다. 다음 형식 없이는 기준으로 채택 금지.

```
### 기준: <이름>
- 규칙: <정량값/범위>
- 근거: <출처 — 실측 노드 / exemplar 캡처 / references 항목 / 벤치마크>
- 신뢰도: 확정(실측·복수관측) | 잠정(1회) | 추측(근거없음, 임시)
```

예 — 원본을 개정하면:

```
### 기준: 카드 radius
- 규칙: 10~14px
- 근거: ❌ 없음 → 신뢰도 "추측". 채택 보류.
- 조치: exemplar 5개 실측 or 토스/네이버 DS 참조 후 확정 승격
```

> **"추측" 신뢰도 기준은 시안 생성에 쓰되 감점 대상.** 확정/잠정만 품질 게이트 통과. 이게 원본의 자기모순("근거 없는 숫자로 근거 없는 AI를 막겠다")을 푸는 장치.

---

## 4. 소스 게이트 (원본 7단계 앞에 삽입)

온사이트 실증: 같은 기능을 PRD추측(드로어) vs Figma실측(모달)로 만들자 진입형태·상태표현이 빗나감.

| 입력 | 규칙 |
|------|------|
| **기준 시안 있음**(Figma 등) | 실측 충실도 우선. 진입형태·색·간격·상태표현 그대로. 3시안은 **variant 탐색**용으로만. |
| **브리프 텍스트만** | 구조·흐름은 Seed/Visual/Pattern으로 생성. 단 **비주얼 결정(진입형태·상태표현·레이아웃)은 3시안 후 사용자 게이트**로 확정. AI 단독 확정 금지. |

## 5. 검수 개정 — 점수 → 이진 + 앵커

원본 "Visual Director/Governor 80점"은 LLM 자기채점이라 재현 안 됨. 개정:

### Governor (시스템화) = 이진 체크리스트 (grep/스크립트 자동화 가능)
- [ ] 토큰화 가능값에 raw 없음 (자동)
- [ ] 컴포넌트 재사용 구조 (자동/반자동)
- [ ] 상태값(빈/로딩/에러) 정의됨
- [ ] Full DS Template 항목 매핑됨
- [ ] 접근성 하한(대비·포커스) 통과 (자동)
→ **전 항목 PASS만 통과.** 점수 아님.

### Visual Director (심미) = 앵커 대조 (LLM 단독 점수 금지)
- 좋은 exemplar N개 · 나쁜 예(AI냄새) N개를 **같이 제시**하고 상대 위치 판정
- 판정 = "exemplar 하한 이상인가?" 이진. + 어긋난 항목 지적
- **복수 관점**(위계/절제/밀도/카피) 각각 이진, 과반 통과

---

## 6. Exemplar 라이브러리 (신규 자산)

"AI UI 냄새"는 금지리스트로 안 잡힌다(gradient 금지는 쉬운 것뿐). 진짜 냄새 = 간격 리듬·위계·카피의 미묘함.
→ **좋은 실제 제품 캡처**를 카테고리별 적재(references/industry-examples 확장). 안티패턴(하지마)만큼 exemplar(이렇게)가 필요.

- `exemplars/{b2b,productivity,expert-tool}/` — 캡처 + 왜 좋은지 1줄 + 실측 토큰(radius/spacing/컬러비율)
- 이 실측이 §3 근거의 소스가 됨 — 순환 해결

## 8. 원본 12단계 → 개정 매핑

| 원본 | 개정 |
|------|------|
| 1 PRD (Superpowers) | 유지 + **소스 유무 분기 명시**(§4) |
| 2 파일기반 기준문서 | 유지 + `rule-schema.md`·`exemplars/` 추가 |
| 3 Global Standard | 유지 + 안티패턴에 **exemplar 대응쌍** |
| 4 Seed | **구조값만** 소유(§2) |
| 5 Visual Direction | **적용 강도만** 소유(§2) |
| 6 Product Pattern | 유지 (우리 rulebook/patterns와 동형) |
| 7 3시안 | 유지 + **소스 게이트**(§4) 선행 |
| 8 검수 | **점수→이진+앵커**(§5) |
| 9 선택+이유 | 유지 + 이유→DS **브릿지 규칙** 필요(후속) |
| 10 Full DS | 유지 |
| 11 토큰/스펙/코드 | 유지 (DS-sync 누적 강제) |
| 12 다화면 확장 | 유지 = 진짜 성공 게이트 |

## 9. 한 줄 결론

원본은 **"정성을 정량으로"**가 핵심인데 그 정량값의 **근거장치**가 없었다. 이 개정판은 rulebook 스키마(근거+신뢰도+게이트) + exemplar + 이진검수로 그 구멍을 메운다. 나머지 골격은 원본 그대로 탄탄.

### 남은 후속 (근거 필요)
- 9단계 "선택 이유(자연어) → Full DS 반영"의 기계적 브릿지
- exemplar 초기 적재 (실측 토큰 뽑기)
- Seed/Visual 라이브러리 초기 3종씩 정량화
