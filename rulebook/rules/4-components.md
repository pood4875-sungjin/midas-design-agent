# Node 4 — 컴포넌트 조합 / 레시피

선택된 패턴 → DS 컴포넌트 결정론 조립. 슬롯↔필드 매핑(규칙기반 + 애매 시 LLM 폴백).
DS 실물: `onsite-designsystem/components/` (button·dropdown·gnb·input·loading·pagination·selection·tag·avatar·modal).

## 레시피는 패턴이 소유 → [patterns/]

각 패턴 파일에 컴포넌트·골격·슬롯바인딩·variant 명시. 여기선 조립 규칙만.

### R-4.1: 없는 컴포넌트는 토큰 스냅해 신규 축적
- 조건: 패턴이 요구하는 컴포넌트가 DS에 없음
- 결정: `mda-onsite-ds-sync`로 신규 컴포넌트 생성(토큰 참조, raw 금지) → components/ + DESIGN-SYSTEM.md
- 근거: 멤버빌드에서 tag·avatar·modal·btn--danger 신규 축적
- 신뢰도: 확정

### R-4.2: 슬롯 매핑 규칙기반 우선
- 조건: 패턴 슬롯 ↔ 엔티티 필드
- 결정: 이름/타입 규칙 매칭, 애매하면 LLM 폴백 (ARCHITECTURE 확정)
- 신뢰도: 확정

## 권한 위계 게이팅 (신규 차원 — 멤버빌드)

### R-4.3: 역할별 액션 노출 매트릭스
- 조건: 액션이 역할 권한에 종속(패밀리 F 등)
- 결정: 렌더 관점 역할 기준으로 액션 노출/비활성.
  - 통합관리자: 전권(초대·역할변경·제거·요청수락). **단 다른 통합관리자·본인 제거 비활성**.
  - 현장관리자: 현장관리자 초대·수락만. 그 외 숨김/비활성.
- 근거: 멤버관리 PRD 권한 위계 + 드로어 빌드
- 신뢰도: 확정

### R-4.4: 파괴적 액션 = danger 버튼 + 확인 모달
- 조건: 제거·삭제 등 되돌리기 어려운 액션
- 결정: `.btn--danger` + 확인 다이얼로그([patterns/overlays] 확인형), 결과 파급 문구 고지
- 근거: 멤버 제거 모달
- 신뢰도: 확정
