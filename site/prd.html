PRD — MIDAS Design Agent

기획 Agent 산출물을 입력받아 디자인 컨셉·디자인 시스템·다중 페이지 UI·프로토타입을 생성하는 AX 기반 Design Agent. 단순 화면 생성이 아닌 제어 가능한 생성이 목표.

1. 비전

요구사항 → 기획 Agent(PRD/IA/Flow/UX정책/와이어프레임) → Design Agent(컨셉·시스템·페이지·프로토타입) → Development Agent(코드·배포)로 이어지는 AX 제품 개발 파이프라인. 현재는 그 중 Design Agent만 구현한다.

2. 문제 정의

현 생성형 디자인 도구는 결과를 만들 수는 있으나 제어가 안 돼 실무 적용이 어렵다. 제품마다 UX 정책·디자인 시스템·화면 구조·컴포넌트 규칙이 다르기 때문. → 단순 생성이 아닌 "제어 가능한 생성"이 필요.

3. 핵심 가설

모든 디자인을 생성할 순 없다. 그러나 반복적으로 쓰이는 UI 영역(Dashboard·List·Detail·Form·Monitoring·Setting)은 패턴화 가능하다. UX 정책·디자인 시스템·컴포넌트·레이아웃 패턴을 정의하면 상당 부분 자동 생성 가능.

4. 목표 / Non-goals

MVP 포함

  • 컨셉 생성
  • 디자인 시스템 생성
  • 다중 페이지 생성
  • HTML 출력

제외 (이번 범위 아님)

  • 자유형 마케팅 페이지 / 브랜딩 비주얼 생성
  • 자동 배포 · Frontend 코드 생성

5. 생성 프로세스

Step 1기획 Agent 결과 입력 (PRD/IA/Flow/UX정책/라이팅/페이지정의/와이어프레임)
Step 2디자인 컨셉 생성 — 최소 3개(Enterprise/Modern SaaS/Data Focused), 사용자 선택
Step 3디자인 시스템 생성 — Color/Typography/Grid/Spacing/Component/Graphic
Step 4다중 페이지 UI 생성 — Login/Dashboard/List/Detail/Setting
Step 5프로토타입 생성 — 페이지 연결·사용자 흐름
Step 6산출물 — HTML (→ 이후 Figma)

6. 구현 원칙

LLM = 요구사항 분석 · 패턴 선택 · 컨셉 생성. 실제 UI 생성은 Design Token · Component Library · Pattern Library · Layout Recipe 기반 결정론적 생성. LLM이 모든 걸 결정하지 않는다.

7. 성공 기준 (현 단계)

  • Gate 0 — 온사이트 Figma 시안을 역설계해 만든 DS로 화면을 재생성했을 때, 원본 시안과 시각적으로 거의 일치. DS 완성도 입증.
  • Gate 1 — 같은 기획 입력 → 매번 일관된 결정론 출력. LLM 직접 생성보다 안정적.

8. 테스트 베드 — 온사이트(Onsite)

컨셉 생성은 일단 건너뛰고, 실제 제품 온사이트의 디자인 시스템을 정답지로 탑재. Figma 시안에서 DS를 역설계 → master md로 고도화 → 그 DS로 기획/자연어 입력 시 산출물을 뽑을 수 있는지 Claude로 먼저 검증 후 제품화한다. 컨셉 3종 생성은 references md 탑재 후 후속 결합.
