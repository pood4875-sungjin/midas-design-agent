이번주 정리 — 디자인 에이전트

2026-07-02 · 분산되어 진행한 3갈래 + 인사이트 + 다음주 할 일
이번주는 각각 따로 굴린 3갈래였음 — ① 온사이트를 DS로 시스템화, ② 생성 파이프라인의 판단근거(정책) 세우기(rulebook), ③ 한국 기업 DS 탑재 테스트. 세 갈래가 결국 "판단근거 파이프라인" 하나로 수렴함.

이번주 한 것 3 tracks, done separately

1

온사이트 → 시스템화 DS 구축

온사이트 제품을 디자인 시스템으로 정리 중. 토큰·컴포넌트 누적.

파이프라인이 준수해야 할 기준 DS 역할.

2

정책 / 판단근거 파이프라인 핵심

PRD·시안 → 온사이트 DS 준수 화면을 "사람이 만든 것처럼" 생성하는 판단 기준서(rulebook)를 세우는 중.

IA·레이아웃·UX축·컴포넌트·토큰·audit 각 단계의 결정 규칙 + 패턴 카탈로그.

rulebook 열기 ↗
3

한국 기업 DS 탑재 테스트 실측

한국 기업 DS를 가져와 에이전트에 탑재 후 따로 테스트. DS가 실제로 맞물리는지 확인.

정책 파이프라인 = rulebook what it actually is

입력: PRD 텍스트 또는 Figma 노드
1 IA→ 2 레이아웃→ 3 UX축(7)→ 4 컴포넌트→ 5 토큰→ 6 audit
각 노드마다 rulebook 조회 → 규칙 있음: 결정론적 적용 · 규칙 없음(gap): 신규 규칙 제안 → 사용자 승인 → 파일에 누적 → 적용.
소스 경계: Figma 있음 = 실측 그대로(추측 금지) · PRD만 = 구조는 생성, 비주얼은 게이트로 확인.

인사이트 why this matters

결국 필요한 건 판단근거 파이프라인을 세우는 것. 그걸 온사이트 시안을 하나씩 던지면서 — 맞게 나오는지, DS·정책대로 나오는지 — 계속 검증해야 신뢰할 수 있음. 규칙은 관측할수록 "잠정 → 확정"으로 승격되고 파이프라인이 단단해짐.
