온사이트 화면을
7개 유형으로 분류했다.

AI가 화면을 자동 생성하려면, 먼저 "온사이트엔 어떤 종류의 화면이 있나"를 알아야 한다. 실제 화면 약 60개를 분류한 결과 — 모두 7종에 들어갔다.

겉모습이 아니라 "목적"으로 가른다

1단계 · 껍데기 걷어내기

분류 전에 아래를 벗기고 목적만 남긴다. 이게 화면 수를 종류 수로 줄이는 핵심.

✕ 상태 — 빈 화면·입력중·업로드중·완료
✕ 표면 — 모달·위저드·도면 캔버스·인라인 편집

→ "단면 추가 모달"도 "완료 화면"도 목적은 등록 → 같은 종류.

2단계 · 목적 질문 7개

지도 위 위치로? → 지도형
여러 항목 표로? → 목록형
한 대상 깊이? → 상세형
여러 지표 차트? → 모니터링형
시간축(단계)? → 일정/간트형
값 넣고 저장? → 등록/설정형
정적 보고/인쇄? → 보고서형

이 7개 질문이 곧 "AI가 화면 종류를 고르는 규칙"의 초안이 된다.
7종 × 실제 온사이트 화면

이렇게 생긴 화면들이 — 7칸에 다 들어갔다

1지도형 Map
지도 위에 현장 위치·위험도를 핀으로 표시. 전체 지도 화면.
위치로 보여줘?
2목록형 List
센서를 표로 나열. 행마다 상태 색. 페이지네이션.
여러 항목 표로?
3상세형 Detail
한 센서 깊이 — KPI+차트+표. 표면=모달. (가장 흔함)
한 대상 깊이?
4모니터링형 Dashboard
여러 센서 종합 차트(통합보기). 어느 게 튀나 한눈에.
여러 지표 차트?
5일정/간트형 Schedule
공정 관리 — 시공 단계를 시간축(간트)으로. 표 같지만 시간축.
시간축(단계)?
6등록/설정형 Form/Setup
계측기 설정 — 값 넣고 저장. (파일 업로드 위저드도 같은 종류)
값 넣고 저장?
7보고서형 Report
주간 현황 요약 보고서. 정적 문서, 인쇄/공유용.
정적 보고/인쇄?

화면 수만큼 설명서를 쓰면 끝이 없다. 목적으로 묶으면 7종 → 종류마다 설명서 1장이면 AI가 같은 종류 화면을 다 만든다. 이게 "제어 가능한 생성"이 가능해지는 이유다. (PRD 가설 "소수 패턴으로 수렴" 이 데이터로 확인됨)
