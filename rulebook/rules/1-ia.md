# Node 1 — IA / 아키타입 판정

입력 PRD/시안 → 목적·엔티티·핵심태스크 추출 → 아키타입 패밀리 판정.

## 아키타입 패밀리 (bootstrap 24화면 근거)

| 패밀리 | 신호(태스크) | 대표 |
|--------|-------------|------|
| A. 모니터링/조회 | 위치·상태 실시간 파악 | 지도뷰·리스트뷰·현장요약 |
| B. 데이터관리(CRUD) | 표 기반 등록·편집·상태전이 | 계측데이터·시공현장·공정관리 |
| C. 해석/결과 | 계산결과 판독·비교 | 최신 해석결과·보완설계안 |
| D. 보고서 | 생성·열람·문서화 | 정기/맞춤·뷰어 |
| E. 설정/온보딩 | 다단계 입력·모드선택 | 프로젝트 초기설정 |
| F. 멤버/권한 | 초대·요청·역할관리 | 멤버관리(신규, 2빌드) |

## 규칙

### R-1.1: 태스크 → 패밀리 매핑
- 조건: 핵심태스크가 "위치+상태 파악"
- 결정: 패밀리 A
- 근거: bootstrap 지도뷰/리스트뷰
- 신뢰도: 확정

### R-1.2: 표+행별 편집/상태전이 → B
- 조건: 엔티티가 목록형 + 행마다 편집·삭제·상태
- 결정: 패밀리 B, 데이터표현=관리테이블([patterns/data-representation])
- 근거: 계측데이터관리·시공현장정보
- 신뢰도: 확정

### R-1.3: 멤버/역할/초대 → F
- 조건: 사람·역할·초대/요청 엔티티
- 결정: 패밀리 F. 관리 UI는 모달 or 드로어(진입형태는 Node2 R-2.x)
- 근거: 멤버초대 Figma 시안(12774:40857)
- 신뢰도: 확정

### R-1.4: 신규 하위형은 게이트
- 조건: 태스크가 기존 6패밀리에 안 맞음(예: 실시간 이벤트 스트림)
- 결정: 제안 → 사용자 승인 → 패밀리/하위형 추가
- 신뢰도: 규칙(메타)
