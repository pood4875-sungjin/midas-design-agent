# 화면 유형 분류 (archetype coverage) — 온사이트

> STEP 0 산출물. 온사이트 화면을 종류(archetype)로 분류해 "총 몇 종류인지" 데이터로 확정한다.
> 원칙: **화면 수 ≠ 종류 수.** 같은 종류의 다른 상태/모달은 한 종류로 묶는다.
> 분류 근거 = Figma frame/text 구조 (원본). 추측 아님.

## 분류하는 법 (How to classify) — 가장 중요

> **화면 종류는 "목적"으로 가른다. "겉모습(표·캔버스·모달)"으로 가르지 않는다.**

겉모습으로 가르면 종류가 폭발한다. 목적으로 가르면 기획 입력 신호로 라우팅할 수 있고 수가 적게 유지된다.

### 1단계 — 껍데기 걷어내기 (먼저)
분류 전에 아래를 벗기고 **알맹이(목적)** 만 남긴다. 이게 화면 수를 종류 수로 줄이는 핵심.
- **상태**: 빈 화면 / 입력 중 / 업로드 중 / 완료
- **표면(컨테이너)**: 모달 / 위저드(스텝퍼) / 도면 캔버스 / 인라인 편집
- → "단면 추가 모달"도 "업로드 완료"도 목적은 **등록** → 같은 종류.

### 2단계 — 목적 질문 7개로 깔때기 (위에서부터, 맞으면 확정)
```
지도 위에 위치로 보여줘?     → 지도형 (Map)
여러 항목을 표로 늘어놨어?    → 목록형 (List)
한 대상을 깊이 파고들어?      → 상세형 (Detail)
여러 지표를 종합 차트로?      → 모니터링형 (Dashboard)
시간축(단계/일정)으로 관리?   → 일정/간트형 (Schedule)
값 넣고 저장하는 게 핵심?     → 등록/설정형 (Form/Setup)
정적으로 정리해 보고/인쇄?    → 보고서형 (Report)
```
이 7개 질문 = AI의 화면 종류 선택룰(requirement routing) 초안.

### 주의 (실제로 틀렸던 케이스)
- **단면 등록**: 겉모습(평면도+드래그) 보고 "도면 에디터형"으로 오판 → 목적이 "등록"이라 등록/설정형으로 흡수. *겉모습에 속지 말 것.*
- **공정 관리**: 표처럼 생겼지만 시간축(간트) → 목록형 아님 → 일정/간트형.

> 캔버스·모달·표는 종류가 아니라 그 목적이 쓰는 **표면/서브패턴**이다.

## 누적 종류 목록 (현재 7종)

| # | 종류(목적) | 한마디 | 처음 등장 |
|---|---|---|---|
| 1 | 지도형 (Map) | 지도 위 위치별 모니터링 | 지도뷰 |
| 2 | 목록형 (List) | 표로 찾기·정렬·비교 | 리스트뷰 / 계측데이터 관리 |
| 3 | 보고서형 (Report) | 주기 요약·정적 문서 | 현장 요약 |
| 4 | 등록/설정형 (Form/Setup) | 데이터·파일을 등록·설정하고 저장 | 계측데이터 등록(단면) / 계측기 설정 |
| 5 | 상세형 (Detail) | 단일 객체 깊이 보기(차트+표+도면) | 센서 상세 / 단면 상세 / 시공 현장 정보 |
| 6 | 모니터링형 (Dashboard/Monitoring) | 여러 지표 종합 차트로 모니터링 | 통합보기 |
| 7 | **일정/간트형 (Schedule/Gantt)** ★신규 | 작업 단계를 타임라인으로 관리 | 공정 관리 |

> 약 61화면(서비스홈 3 + 단면등록 9 + 계측데이터 19 + 현장관리 33, 일부 흐름 중복)을 던졌으나 모두 **7종**에 수렴.
> PRD 가설은 "6종"이었으나 실측 결과 **7종**(간트형 추가). 핵심("반복 UI는 소수 패턴으로 수렴")은 검증됨.
> **상세형이 가장 빈도 높음** — 모달·도면 캔버스·인라인 편집을 표면으로 두루 씀.

서브패턴(표면) — 종류 아님, 여러 종류가 공유하는 도구:
- **모달**: 상세형·등록형이 자주 쓰는 컨테이너 (센서 상세, 단면 추가, 알림/확인)
- **위저드(스텝퍼)**: 등록형의 다단계 표면 (업로드→추출→연결→맵핑→완료)
- **도면 캔버스**: 평면도에 객체 배치 + 레이어/줌 (등록형의 작업 표면)
- **인라인 테이블 편집**: 설정형의 표면 (계측기 설정)

> 처음엔 겉모습 보고 "도면 에디터형" 7번째 유형을 잡았으나, **목적이 "등록"** 임이 확인되어 등록/설정형으로 흡수. 캔버스·모달·위저드는 종류가 아니라 표면.

## 교훈 (분류에서 나온 것)
1. **목적으로 가른다, 겉모습으로 가르지 않는다.** 도면 캔버스·표·모달은 종류가 아니라 표면. (이번에 "도면 에디터형"으로 잘못 잡았다가 "등록/설정형"으로 교정.)
2. **던진 화면 수만큼 설명서를 쓰지 않는다.** 9화면 → 설명서 1장(등록/설정형) + 표면·상태별 메모.
3. **상태(빈/배치/업로드/완료)와 표면(캔버스/모달)은 종류 안의 변형.** 설명서에 "표면"·"상태" 절로 묶는다.
4. 새 화면이 기존 종류에 안 맞으면 → 그때만 새 종류 추가. 미리 늘리지 않음.

## 남은 일
- 등록/설정형 설명서 1장 (표면: 도면 캔버스 / 입력 모달, 상태: 빈/배치/업로드/완료).
- 다른 메뉴(계측 통합보기·결과·해석·보고서·설정 등) 화면도 같은 방식으로 분류 누적.
